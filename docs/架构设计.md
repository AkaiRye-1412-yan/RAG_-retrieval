# AkaiRye 知识RAG平台 — 架构设计

> 本地优先的 Windows 桌面 RAG 应用。FastAPI + Vue3 + LangChain(LangGraph) + pywebview，
> PyInstaller 打包为 onedir 文件夹发布。本文描述实际代码实现（与最新代码保持一致）。

---

## 1. 项目概述

| 项 | 说明 |
|---|---|
| 定位 | 完全本地优先的私有知识库问答桌面程序 |
| 对话 | 优先检索本地向量库；命中不足时自动经 Tavily 联网搜索 |
| 记忆 | 多会话上下文，全部持久化在单个 SQLite 文件 |
| 向量 | **自研** SQLite 向量存储（float32 BLOB + numpy 余弦），无 Chroma/FAISS 重依赖 |
| 密钥 | 全部在 exe 同目录 `.env`（**不打包**），系统配置页热修改即时生效 |
| 发布 | PyInstaller **onedir**，目标机无需 Python，仅需 Edge WebView2 Runtime |
| 联网 | 除调用方舟/Tavily 接口外**无任何隐藏下载**（OCR 模型、前端均随包内置） |

## 2. 技术栈

**后端**（Python 3.12，uv 管理）
- FastAPI + uvicorn 0.53（`loop=asyncio, http=h11`，无 uvloop/httptools）
- langchain 1.3.x、langchain-openai（OpenAI 兼容 → 火山方舟）
- langgraph 1.2.x（手写 `StateGraph`，不用已弃用的 `create_react_agent`）
- numpy<3（向量计算）、pymupdf（PDF）、python-docx、openpyxl、xlrd
- rapidocr-onnxruntime 1.4.4（离线 OCR，模型内置 wheel）、pillow
- tavily-python、pydantic-settings、python-dotenv
- 标准库 `sqlite3`（WAL），不引 SQLAlchemy

**前端**（Node.js + Vite 6）
- Vue 3 + Pinia（不用 vue-router，Pinia 切换三个视图）
- markdown-it + highlight.js + DOMPurify（Claude 风格 Markdown 渲染）
- lucide-vue-next（图标）

**桌面壳**：pywebview 6.x（EdgeChromium / WebView2）

## 4. 运行模式

### 4.1 开发态
- `scripts\dev.bat`：开两个终端，后端 `uvicorn ... --reload --port 8000`（Swagger 在
  `http://127.0.0.1:8000/docs`），前端 Vite `http://localhost:5173`（`/api` 代理到 8000）。
- `set AKAIR_DEV=1 & uv run akairye-rag`：桌面壳联调，窗口指向 5173。
  **注意**：`AKAIR_DEV=1` 时 launcher 不自己起后端（见 `launcher.py:57`），需先手动跑 uvicorn。
- 开发态读**项目根目录** `.env` 与 `data/`（与打包版相互独立）。

### 4.2 打包态（产物目录）
```
dist/AkaiRyeRAG/
├─ AkaiRyeRAG.exe      # 启动入口（21MB）
├─ _internal/          # 全部运行库 + OCR 模型 + 前端 dist（313MB，不可缺）
├─ .env                # 首启自动生成（绝不打包；含真实密钥）
└─ data/               # akairye.db + uploads/ + logs/
```
- `launcher.run()`：空闲端口探测 → 守护线程起 uvicorn → 轮询 `/api/health`（≤20s）
  → pywebview 开窗（1440×900，EdgeChromium）→ 关窗 `server.should_exit=True`。
- 目标机要求：Windows 10/11 + Microsoft Edge WebView2 Runtime，**无需 Python**。

## 5. 配置模型与热更新（core/settings.py）

- `Settings`（pydantic-settings）按需从 `.env` 构造快照；每次请求用当前快照构建
  LLM/Embedding 客户端 → **保存设置后下一次请求立即生效**（`DATA_DIR` 除外，需重启）。
- `SettingsStore.write_updates`：对 `.env` **读改写**——保留注释与未知键，只替换已知键的行，
  新键追加到文件末尾。保存后 `load_dotenv(override=True)` 重建单例。
- 密钥字段：留空=不修改；API 只回显 `configured` 布尔 + `last4` 掩码，永不返回明文。
- 向量模型维度白名单（保存时校验，防止「改了维度上传全 400」）：

```python
EMBEDDING_DIMS_BY_MODEL = {
    "doubao-embedding-vision":     (2048,),                    # 仅支持 2048
    "doubao-embedding-text-240715": (2048, 1024, 512),
}
```

- PUT `/api/settings` 时：目标维度不在模型白名单 → 400 中文报错且**不写入**；
  维度改变且知识库已有数据 → 返回 `warn`，前端提示先「重建索引」。

### 5.1 `.env` 主要变量
| 变量 | 说明 |
|---|---|
| `ARK_API_KEY/BASE_URL/MODEL` | 对话模型（OpenAI 兼容；模型 ID 或 `ep-` 接入点） |
| `EMBEDDING_MODEL/BASE_URL/KEY` | 向量模型；KEY/BASE_URL 留空回退 ARK 配置 |
| `EMBEDDING_DIM/BATCH` | 输出维度 / 每批条数（套餐端点上限 10） |
| `TAVILY_API_KEY` | 联网搜索；配置 Key 即可用，是否联网由 `TOOL_MODE` 决定 |
| `TOOL_MODE` | `auto` 自决 / `on` 强制工具 / `off` 纯知识库（不联网） |
| `TOP_K/SIMILARITY_THRESHOLD` | 检索返回条数与阈值（默认 6 / 0.30） |
| `CHUNK_SIZE/CHUNK_OVERLAP` | 切分参数（500 / 80） |
| `HISTORY_LIMIT` | 每会话注入上下文的消息条数（12） |
| `OCR_ENABLED/OCR_DPI` | 离线 OCR 开关 / 扫描页渲染 DPI（200） |
| `DATA_DIR/VECTOR_CACHE` | 数据目录 / 向量矩阵是否驻内存 |

## 7. 核心流程

### 7.1 上传 → 入库（ingest/）

```
POST /api/documents/upload (multipart)
  → 落盘 data/uploads/<doc_id><ext>，建 documents(pending) 记录
  → 返回 job_id（JobManager 后台线程串行执行）

JobManager._process_one：
  parsing    parse_file → 按类型提取文本
  splitting  RecursiveCharacterTextSplitter（中文分隔符序，500/80，溯源前缀+locator）
  embedding  SQLiteVectorStore.add_fragments(…, batch_size=EMBEDDING_BATCH, on_progress)
             → 每批嵌入成功即提交入库，回调刷新 documents.chunk_count
  done       status=done，chunk_count=n
  任一步失败 → status=error(error 摘要)，不影响其它文件
```

**支持的格式**（parsers.py `SUPPORTED_EXTS`）：
`pdf / doc / docx / xls / xlsx / csv / txt / md / log / png / jpg / jpeg / bmp / webp / tif / tiff`

- PDF：pymupdf 逐页取文本；单页 <10 字判定为扫描页 → `get_pixmap(dpi=OCR_DPI)` 送 RapidOCR。
- `.doc`：尝试 PATH 中 LibreOffice 转换，否则明确报错引导另存 `.docx`。
- xlsx：openpyxl（read_only/data_only，日期特判，逐 sheet）；xls：xlrd。
- 文本：编码回退链 `utf-8-sig → gb18030 → latin-1`。
- 图片：Pillow + RapidOCR（`ocr.py` 全局懒加载单例，`OCR_ENABLED=false` 可关）。
- Excel 按行累积成块且每块带表头；每块带溯源前缀《文件名》第N页/表名，locator 存 page/sheet。

**恢复机制**：程序异常退出后再启动，`app_context.py` 会把卡在
`pending/parsing/splitting/embedding` 的文档标记为 `error`（“程序重启导致中断，
请在向量库页执行「重建索引」”），并清空半成品 chunks 依赖的维度由重建处理。

**重索引**：`POST /api/documents/reindex` = 清空 chunks 后按 `data/uploads/` 全量重跑。

### 7.2 嵌入与限流（retrieval/sqlite_store.py）

火山方舟**套餐端点**（`/api/plan/v3`，标准 `/api/v3` 对套餐 Key 返回 401）的实测约束：
- 每批嵌入上限 **10** 条（`max 10, got N`）→ `_embed` 从报错解析 `max N` **自动降批**重试；
- 约 **6 次/分钟** 限流（`429 AccountRateLimitExceeded`）→ 内置限速器：

```python
MAX_429_RETRIES = 30     # 单批最多退避次数（足以跨越数分钟的严格限流窗）
_BACKOFF_STEPS = (3, 6, 10, 12)   # 连续 429 的退避序列，之后稳定 12s
BASE_PACE_SECONDS = 1.0  # 未遇限流时的批间间隔
MAX_PACE_SECONDS = 12.0  # 学到的最大批间间隔（不回弹）
```

- `_call_with_rate_guard(fn)`：捕获 `RateLimitError`（优先取 `retry-after` 头），
  退避后重试；撞过限流就永久拉大后续批间间隔。
- `OpenAIEmbeddings(max_retries=0)`：**关闭 SDK 内部重试**，节奏完全由本地限速器控制。
- 维度错误（如 vision 模型配 512）→ `BadRequestError` 中带 `dimensions` → 抛出中文
  `ValueError`，引导去系统配置改维度或重建索引（见 `_embed` 的 `dimensions` 分支）。

### 7.3 检索（自研向量存储）

- 写入：向量 L2 归一化后 `numpy.tobytes()` 存 `chunks.embedding` BLOB，与文本同事务。
- 维度一致性：`kv.embedding_dim` 记录首个写入维度；新向量维度不一致 → 拒绝并提示重建索引
  （`_check_or_set_dim`）。
- 缓存模式（`VECTOR_CACHE=on`，默认）：全量矩阵 `(ids, doc_ids, V[float32])` 驻内存，
  检索 = `V @ q` + `argpartition` top-k + 按分片取文本（20 万分块约百毫秒级）。
- 无缓存模式（`off`）：`SCAN_BATCH=10_000` 分批流式扫描 + `heapq` 维护 top-k，内存有界。
- `search(query, k, threshold, filter=doc_id)` 返回 `[{id,doc_id,seq,content,locator,score}]`，
  已按 `SIMILARITY_THRESHOLD` 过滤，score 为余弦值。

### 7.4 对话 Agent（agent/，LangGraph）

每次问答按当前 settings 快照构建一张状态图（`graph.py: build_chat_graph`）：

```
START
  └─ retrieve（预检索：按路由做「单产品硬过滤」或「多产品分组检索」；
              writer 推 knowledge_search start/end 事件）
       ├─ TOOL_MODE=off → generate_direct（纯 RAG 链，不绑工具，按资料说话，禁止编造）→ END
       └─ auto / on     → agent（有界工具循环 ≤3 轮）→ END
```

- **知识库优先、无答案才联网**是确定性的：`retrieve` 阶段先检索并注入带 `[1]..[n]` 编号的
  片段；`build_system_prompt`（prompts.py）按命中情况翻转指令——知识库未命中且 Tavily 可用时
  明确要求调用 `tavily_web_search`；未命中且无联网时如实告知用户，不臆造。
- agent 循环：`ChatOpenAI.bind_tools(tools, tool_choice=…)`；`on` 模式首轮
  `tool_choice="required"`，个别模型返回 400 时自动回退 `auto` 并在提示词强制（graph.py:87-96）。
- 工具（tools.py）：
  - `knowledge_search(query)`：再检索本地库，返回编号片段；
  - `tavily_web_search(query)`：联网搜索；仅当 `s.tavily_usable`（有 Key 且开启）才挂载。
- 记忆：**不用 checkpointer**。每请求从 SQLite 取该会话最近 `HISTORY_LIMIT` 条消息作为上下文；
  问答结束后 user/assistant 消息（含 sources / tool_events / used_web）落库。
- 引用编号：预检索片段 + 工具返回片段统一顺序编号，`[n]` 角标对应前端的引用列表。

#### 7.4.1 检索分流（retrieval/router.py）

多品牌知识库（高创 / ACS / AGITO / AKRIBIS …）先分层再检索，规则确定性、不额外调用模型：

1. **文档归类**：`document_product_map(ctx)` 按「文件名 + 前 3 个片段正文」匹配产品目录
   `PRODUCTS`（品牌别名强匹配、型号前缀弱匹配），结果缓存在 `AppContext`，文档增删/改块数后自动重算。
2. **问题识别**：`analyze_query(query, previous_user_texts, product_map)` →
   - 明确出现品牌名 → `Route(source=explicit, doc_ids=该产品文档)`，向量检索时用
     `filter={"doc_ids": …}` 做**文档级硬过滤**，只答该产品；本轮点名的产品同时刷新会话范围。
   - **会话产品上下文**：`session_products(...)` 从本会话用户提问（`chat.py` 取最近 40 条，
     不受 `HISTORY_LIMIT` 限制）倒序找出最近一次的产品范围表态；本轮未点名品牌但会话已有范围时
     → `Route(source=context)`，同样用 `doc_ids` 硬过滤，只检索/只回答该产品。
     提问「那高创呢」会命中 explicit 并切换范围；明确要求「其他产品 / 全部产品」则解除范围，
     回到 `multi`，后续追问也保持跨产品覆盖，直到再次点名某产品。
   - **本会话首次模糊提问（从未确定过产品）→ `Route(source=multi)`**：`retrieval_scopes()`
     按产品目录拆出 `[(产品, doc_ids), …]`，再补上未归类文档，交给 `kb_search_multi`
     逐产品检索并合并，保证「如何回零」这类问题把高创 / ACS / AGITO 等的资料全部召回。
   - 提取指令词（`PTP/MST/HOME…`，排除品牌名与常见英文词）；片段正文中精确命中的优先。
   - 模糊提问额外用 `query_variants()` 做轻量同义词扩展（回零→回原点/原点回归/homing…），
     每个产品最多补充 2 条，提升跨厂商术语差异下的召回。
3. **多产品检索实现**：`AppContext.kb_search_multi` 每产品取
   `max(3, min(8, TOP_K))` 条，查询向量只算一次（变体各一次），返回片段带 `product_key`；
   片段在提示词中带【产品】标签，按产品分组编号。
4. **约束注入**：`build_system_prompt(..., route=…)` 在系统提示词里写明约束——
   明确产品 → 「只能依据该产品资料」；会话沿用范围（context）→ 「本会话产品范围为该产品，
   只答该范围，只有本轮点名其他产品才切换」；首次模糊提问 → 「跨产品完整覆盖，按产品分节，
   开头给概览、结尾给对比表，没有资料的产品要说明缺失，不要用其他产品替代」。
   agent 的 `knowledge_search` 工具始终沿用同一 `doc_ids`，防止二次检索绕回全库；
   context 路由还会关闭联网工具（联网结果无法按产品过滤）。
5. **无资料时**：明确/会话锁定产品但库内无对应文档 → 不跨产品补答，提示用户上传该产品资料；
   首次模糊提问跨产品检索后仍无命中 → 先说明已检索全部产品，再按联网/缺资料流程处理。

新增品牌/系列时，只需在 `retrieval/router.py` 的 `PRODUCTS` 里追加 `Product`
（`aliases` 写品牌与系列名，`model_prefixes` 写型号前缀）。

### 7.5 SSE 协议（api/routes/chat.py）

`POST /api/chat/stream`，`text/event-stream`，fetch + ReadableStream 手动解析。
事件按序推送（`data: {json}`，UTF-8）：

| type | 字段 | 说明 |
|---|---|---|
| `meta` | session_id, message_id, tool_mode, tavily | 流开始 |
| `tool` | name(knowledge_search/tavily_web_search), status(start/end), input, hits, top_score, error, items[]；可选 product/tokens/scoped/context（分流信息） | 工具步骤状态；`items` 供引用渲染 |
| `token` | content | 逐 token 正文 |
| `sources` | items[](kind kb/web, doc_name/title, score, snippet, url) | 最终引用列表（去重 + 重新编号） |
| `done` | message_id, used_web | 流结束 |
| `error` | message | 失败（会话不存在 / 未配 Key / 生成异常） |
| `: keep-alive` | — | 注释行保活（20s 无 token 时，`asyncio.shield` 不取消底层图流） |

## 10. 安全设计

1. 后端**仅绑定 `127.0.0.1`**；启动前由 launcher 探测并占用空闲端口。
2. HTTP 中间件校验 `Origin`/`Referer`：带跨来源头的请求必须来自本机回环，防 DNS rebinding。
3. API **永不返回明文密钥**，只给 `configured` 布尔与 `last4` 掩码。
4. `.env` 不打包、不入库，首启自动生成模板；`scripts/build.bat` 与 `akairye.spec`
   均不含 `.env`。
5. OCR/前端等资源全部随包（`_internal`），无运行时隐藏下载。

## 11. 打包与发布

`scripts\build.bat` = `frontend: npm install + build` → `uv sync` → `uv run pyinstaller akairye.spec --noconfirm --clean`。

akairye.spec 要点：
- `collect_all`：rapidocr_onnxruntime、onnxruntime、cv2、shapely、pymupdf、openpyxl、webview；
- `collect_submodules + copy_metadata`：langchain 全家桶 + langgraph，metadata 含
  openai/tiktoken/pydantic/numpy/tavily 等；
- hiddenimports：`tiktoken_ext`、uvicorn 子模块、multipart、pyclipper、six、yaml、xlrd、
  docx、clr、webview.platforms.edgechromium/winforms、bottle、proxy_tools；
- datas：`("frontend/dist","frontend")`；**不含 .env**；
- excludes：chromadb/langchain_community/langchain_classic/faiss/anthropic/pandas/matplotlib/tkinter/pytest；
- EXE：`name=AkaiRyeRAG, console=False, icon=assets/icon.ico`；COLLECT onedir。

发布方式：**整个 `dist/AkaiRyeRAG/` 文件夹**（exe + `_internal`）拷走即用；
`.env`、`data/` 视是否共享密钥/知识库决定是否保留或删除。

## 12. 已知限制与常见问题

- **套餐端点限流慢**：`/api/plan/v3` 每批≤10、约 6 次/分钟，数千分块文档入库约需 1 小时。
  已内置自动降批、退避与分批提交（进度不丢、中断可续）。需要更快 → 方舟控制台为该模型开通
  按量付费后改用标准端点。
- **换模型/维度必须重建索引**：向量维度不一致会拒绝写入（`_check_or_set_dim`），
  `doubao-embedding-vision` 仅支持 2048。
- **打包后改动代码**：改后端 `src/` 需重跑 `scripts\build.bat`；只改前端可仅
  `cd frontend && npm run build` 后把 `dist` 拷进 `_internal/frontend`。
- **杀软误报**：未签名 onedir 首次运行可能被 SmartScreen 拦截，加白名单即可。
- **目标机缺 WebView2**：启动时弹窗提示安装运行时。
